# Android 1.7.40：Pixiv 请求保护

versionCode 99。为 Android 的 Pixiv 画师解析、单作品图片解析、原图下载、Ugoira 帧包下载及图片预览加入共享请求预算与冷却保护，默认启用。

## 行为

- 同一应用安装中的全部 Pixiv 账号和匿名请求共享预算：`pixiv.net` 请求至少间隔 2 秒，`pximg.net` 图片/帧包请求至少间隔 1 秒，两类之间还保留至少 500ms 的全局间隔。控制的是请求发起频率，不限制图片传输带宽；长连接中的在途传输仍可能重叠。
- 原生 OkHttp 和 Python 子进程使用相同的 POSIX 记录锁与原子状态文件。切换账号、修改代理或重启进程不会另开预算或清掉冷却记录；其他平台不消耗该预算。
- 收到 HTTP 429、401/403、登录/验证跳转、异常 HTML，或带 `Retry-After` 的 503，停止后续请求并返回明确错误与剩余等待时间。默认冷却 15 分钟，24 小时内重复触发依次延长到 30、60 分钟。平台要求等待更久时，采用平台的更长时间；支持秒数和 RFC 1123 HTTP 日期，不在冷却期内循环重试。
- 检查在 DNS/TCP/TLS 连接之前执行，防止用户重试或多个任务在冷却期间继续新建连接；HTTP 后续请求也检查预算。已经发送的在途请求无法撤回。Python 的 Pixiv 连接禁用底层自动重试，原生冷却错误使用不可自动恢复的异常类型，不匿名重试或切换出口。
- 原生作品 JSON 缓存有效期 3 分钟，最多 128 条/8MiB；Python 作品 JSON 使用应用私有目录的短期缓存，最多 64 条/8MiB。缓存按 URL、Cookie 和代理范围隔离，不缓存错误结果或 `no-store` 响应。图片预览继续使用已有 Coil 缓存。缓存命中只读取本地结果，不产生网络请求。
- 冷却状态只保存时间、错误类别和触发次数，不保存 Cookie、账号 ID 或代理凭据。写入状态失败会中止请求；损坏状态采用一次 15 分钟保护冷却，不按空状态放行。
- 等待请求许可、读取作品 JSON 和下载 Ugoira 帧包均支持取消。HTTP 保护错误保留原错误码，不再包装成转码错误。

冷却结束后需手动重试；遇到登录或验证要求时也需先解决对应会话问题。画师解析沿用当前会话的逐作品检查点，已生成下载任务继续保留；应用进程重启后需重新解析画师主页，不承诺原图下载的字节级断点续传。缓存条目不代替作品 ID、归属和页码验证。

## 验证

- 276 项 JVM 测试：跨实例共享频率、重启后的冷却、较长 `Retry-After`、重复触发退避、取消、损坏状态保护、Cookie/代理缓存隔离及过期、错误结果不缓存。
- 85 项相关 Python 回归：请求预算、冷却、底层重试关闭、验证响应、缓存范围，以及已有图文、Cookie、X 和画质处理。
- 5 项 Android 15 x86_64 模拟器回归：验证 Java FileChannel 与 Python `fcntl.lockf` 确实互斥，原生许可被 Python 继续遵守，Python 429 冷却被新原生实例读取；受控 HTTP 验证冷却期间没有第二个 Pixiv 连接且其他平台可继续请求；作品 JSON 与 Ugoira GIF/MP4/帧 ZIP 回归通过。
- 单作品在线解析和原图下载单独记录在交付目录 `qa/device-live.log`；没有重复批量下载整个画师图库。正式构建、Lint、签名和正式包 UI 冒烟日志一并交付。

测试期间发现网络拦截器执行时连接已经建立，已增加连接前的应用拦截层，保留最初失败日志。一次既有 HTTPS 代理单元测试出现 Socket closed，保留日志，单独顺序重跑全套通过。

这些间隔是本软件的保守默认策略，不是 Pixiv 官方公布的安全阈值，不能保证不封号，也无法协调浏览器、其他下载器或其他设备的请求。[Pixiv 官方风控说明](https://inside.pixiv.blog/2023/05/17/102629)；[`Retry-After` 规范](https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after)。本次仅 Android，未替换本机 Web、Windows 或 iOS，未公开发布至 GitHub。原生功能在 x86_64 模拟器验证；ARM64 正式包冒烟跳过原生执行，未在实体 ARM64 手机验证。

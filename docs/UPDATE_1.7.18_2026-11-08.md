# OmniDownloader Android 1.7.18

落实抖音自动提取与画质补全方案。粘贴或分享链接后，先读取目标分享页和详情；只有低规格、缺少尺寸或上传参考尺寸更高时，在应用前台自动加载一次目标页面，无需用户主动进入浏览器。自动阶段只收集页面实际返回的数据，不操作验证码。平台明确要求登录或验证时保留当前可用源，并提供内置浏览器入口；验证页面正常返回目标视频后可自动继续读取。

## 行为变化

- 合并同作品的多份媒体数据和各个真实规格；等待延迟返回的高清详情，避免先出现的 720P 提前终止补全。上传参考宽高只用于发现规格缺口，不冒充播放流尺寸。
- 对最高候选使用有预算的 MP4 区间探测，核对实际宽高和源时长。画质面板分别显示尺寸实测证据与补全限制，不将“本次可用最高规格”称为“上传原片”。
- 同规格下保留帧率、动态范围及编码信息，同编码内再比较码率；普通视频沿用原媒体字节下载，分离流沿用无重编码封装，不新增默认画质转换。
- 自动阶段最多一个 WebView，页面预算 15 秒，结果稳定后提前结束；读取捕获结果不反复发起未签名详情请求。关闭页面、取消、切后台或会话改变时释放资源。后台任务可使用 HTTP 和缓存，不主动拉起页面。
- 自动浏览器使用按账号策略代次隔离的 Cookie/存储 Profile，遵守 Cookie 开关。代理由共享租约管理，避免自动页面结束时清除仍在使用的验证页面代理。缺少系统 WebView 所需能力时保留 HTTP 结果并说明限制。
- 解析进度显示正在读取、自动补全与核对尺寸。缓存绑定账号策略和网络；手动捕获、重新登录、清除账号或网络改变后不会继续使用旧范围的结果。

## 限制与使用

安装 `release/1.7.18/OmniDownloader-1.7.18-arm64-v8a.apk` 后重新解析原链接。在应用前台且允许抖音 Cookie、系统 WebView 支持隔离 Profile 时，可自动补全页面数据。遇到明确验证码或登录仍需要用户完成验证；平台未提供或不允许访问的更高规格无法凭空恢复，实际网站成功率也未作统计承诺。

没有连接 ARM64 真机，未完成真实 HDR/高帧率媒体的端到端验收；相应保留和排序策略已由测试覆盖。真实验证完成后自动接续的代码已实现，但本次未进行人工验证码通过后的在线成功验收。未更新 GitHub Release。

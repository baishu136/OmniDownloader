## 代理与稳定性

- 真机崩溃日志确认旧问题为连接池清理在主线程发送 TLS 关闭消息，触发 `NetworkOnMainThreadException`。清理现在在 IO 线程执行，取消时也会完成资源释放。
- 在真机应用页面保持代理输入为空，点击「连通性测试」后，调试构建中国内站点 438ms、国际站点 983ms 均连接成功。安装最终 Release 后再次从真实页面点击，国内站点返回成功（490ms），国际站点返回 TLS／证书错误（5031ms）。两次应用进程均不变、无闪退，没有保存或覆盖代理配置；网络失败正常显示，不计为连接成功。这些是具体采样结果，不代表固定延迟或所有站点连通。
- 主线程调用的原生回归另外完成两轮，没有原来的异常；首轮测试受系统后台冻结影响，耗时不用于性能比较。
- HTTPS 代理使用对代理服务器的 TLS 连接，CONNECT 内部的目标 HTTPS 保留端到端校验。137 项 JVM 测试包含真实本地 TLS-in-TLS 传输及拒绝不可信证书；不使用信任所有证书或协议降级。
- 用户提供的链接返回订阅相关响应信息，不是可直接填写的 HTTPS 代理服务器地址。本轮没有将订阅地址伪装成代理，也没有安装代理客户端或改动系统代理。因此公网 HTTPS 代理端点尚未完成实测。

- 137 项 JVM、36 项 Python 检查通过。APK 的 ARM64 ABI、版本 74 / 1.7.15、归档 CRC、原签名及构建输入校验通过。
- 手机最初的测试辅助包完成了上述 24 条解析检查。新版辅助包安装被系统拒绝，后续分辨率修正改用已安装应用的真实分享入口及随包 Python 运行时检查，没有把未执行的新用例计为通过。
- 小红书与抖音修正均有正式页面截图；空代理测试通过真实设置页面点击完成。补充运行时检查使用匿名会话，不读取账号数据，7 个图文平台的首张样本尺寸均匹配。

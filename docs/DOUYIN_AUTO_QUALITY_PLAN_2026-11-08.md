# 抖音自动提取与画质保留优化方案

状态：已在 Android 1.7.18 落实。下文保留原始设计与验收目标；实际测试结果及未验证项见 [1.7.18 更新说明](UPDATE_1.7.18_2026-11-08.md) 和 [测试报告](TEST_RESULTS_1.7.18.json)。没有承诺平台成功率或所有作品均可免验证。

目标：用户粘贴或分享链接后，应用自动取得目标作品可访问的最高质量媒体源，尽量保留分辨率、帧率、动态范围和编码；普通可访问页面无需用户手动打开浏览器。只有平台实际提供并允许访问上传原文件时，才能将其作为上传原片保存。

## 实施前的问题

1. 原生分享页返回媒体后即可能结束解析；桌面详情补充失败时，720P 列表也会成为最终结果。更高画质仍主要依赖用户手动启动浏览器提取。
2. 一些网页脚本特征被直接归类为 CHALLENGE_REQUIRED，尚未区分普通 JavaScript 加载和明确需要人为操作的滑块、登录页面。
3. 尺寸探测主要针对缺少尺寸的源；最高候选已有尺寸时通常直接采用元数据。已有媒体尺寸、上传参考尺寸与“最高画质已确认”需要分别记录。

## 建议流程

链接归一化和目标 ID 确认 → 会话范围内的已确认缓存 → 原生 HTTP 提取及多规格合并 → 必要时自动页面解析 → 对最高候选做真实媒体探测 → 保存原媒体字节或无重编码封装 → 成品复核。

### 第一阶段：自动补全候选与识别页面状态

- 保留分享页、目标详情和播放器返回的各个真实规格及备份地址，不以首个成功响应覆盖高规格结果。
- 缺少目标详情、只有低规格结果且最高画质尚未确认、或上传参考规格明显高于返回流时，触发一次有预算的自动补全。720P 本身不等于错误，真实 720P 视频仍应正常支持。
- 区分需要 JavaScript 的页面、明确要求登录的页面、可见的人机验证、限流和内容不可用。普通脚本页进入自动解析；明确的人机验证提示用户处理。
- 初始建议每次补全最多使用一个 WebView、约 15 秒页面预算、探测两个最高候选；这些是待实测调整的参数，不是已测性能指标。

### 第二阶段：应用自动加载页面

- 通过专门的 Android 平台适配器管理 WebView，复用现有站点身份、代理和用户允许使用的会话。遵守 Cookie 开关和退出登录状态。
- 在页面脚本执行前安装现有目标作品捕获脚本，自动加载原作品页面，收集真实页面响应中的目标详情、多码率列表和可关联的播放器地址。
- 优先读取详情数据；确需播放器元数据时采用静音、有限加载，避免下载整段视频作为解析前置条件。
- 不要求用户切换到浏览器界面。应用前台只显示解析进度和取消入口；后台下载优先复用缓存或 HTTP 刷新，不擅自启动可见页面。
- 验证码或登录需要交互时，将验证页面交给用户，验证后自动继续原任务。自动页面加载不能保证所有作品都免验证。
- 采用事件驱动的收集方式；读取已收集结果不重复发起相同详情请求。支持取消、超时释放和账户/网络变更失效，避免 WebView 泄漏和反复请求。

### 第三阶段：保真选择与下载

- 必须绑定目标作品 ID；无明确归属的广告、推荐内容、验证动画和占位视频不进入候选。
- 候选按真实尺寸、帧率、动态范围及来源证据筛选；同编码、同规格再比较码率，不能跨 H.264/H.265 单凭码率判断画质。
- 对最终最高候选读取有限 MP4 区间，核对实际尺寸、时长和文件长度；必要时补充编码、HDR 信息。上传参考规格只用来发现可能缺失的画质，不能作为流尺寸。
- 普通视频下载保留原媒体字节；分离音视频采用无重编码封装。HDR、60fps 和 HEVC 不因兼容性被默认转为 SDR、30fps 或 H.264。
- 地址失效时按同作品和已选规格刷新、换源。若只剩更低规格，明确说明，不能把降级成品标为原画。
- 输出状态区分“已验证源规格”“本次最高可用规格”和“上传原片已确认”，避免笼统使用“原画”。

## 验收

- 公开可访问目标在无手动浏览器操作时完成解析与下载；分别记录 HTTP 成功、自动页面成功和需要用户验证的比例。
- 覆盖先返回 720P、稍后出现 1080P，真实原生 720P，竖屏/横屏，HDR/高帧率，以及高码率跨编码比较。
- 验证页存在 1080P 占位动画时拒绝误提取；其他作品 ID 和未关联的播放器源始终被拒绝。
- 覆盖取消、超时、退出登录、Cookie 禁用、代理切换、签名过期和进程重启后的任务恢复。
- 自动提取成功与真实手机、真实平台成功率分开报告；不能以合成页面测试替代在线实测。

## 实施入口与参考

现有 `DomesticDirectExtractor`、`DouyinVideoParser`、`DouyinVideoBrowserScript`、捕获 JS、`HttpMp4Probe` 和 `DomesticSourceRecovery` 均可复用。新增自动页面适配器与解析协调层，避免将 WebView 生命周期直接塞入业务解析器。

- [AndroidX WebViewCompat 文档开始注入接口](https://developer.android.com/reference/androidx/webkit/WebViewCompat#addDocumentStartJavaScript(android.webkit.WebView,java.lang.String,java.util.Set%3Cjava.lang.String%3E))：可在页面脚本之前执行；使用前必须检查组件能力。
- [WebView 媒体手势设置](https://developer.android.com/reference/android/webkit/WebSettings#setMediaPlaybackRequiresUserGesture(boolean))：控制媒体播放是否要求用户手势，不代表可以自动完成登录或验证码。
- [Android 媒体元数据读取](https://developer.android.com/reference/android/media/MediaMetadataRetriever)：用于本地成品尺寸、旋转和时长复核。

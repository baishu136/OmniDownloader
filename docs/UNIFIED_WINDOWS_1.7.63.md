# OmniDownloader Windows 1.7.63 整合版

完整解压 `OmniDownloader-1.7.63-Windows-x64.zip`，双击根目录 `OmniDownloader_WinUI.exe`。保留同目录的 DLL、运行时及 `OmniDownloader_Web` 子目录；不需要安装 Python、.NET、FFmpeg 或 yt-dlp。

## 客户端与网页版

原生 WinUI 客户端负责完整下载功能和配置管理，包含账号、代理、保存目录、并发、登录及引擎设置。精简网页版仅提供单条下载（视频、音频、图文等现有类型）、批量下载、下载进度和深浅色切换。网页不再包含平台名单、账号/代理/引擎设置、升级提示或帮助导航。

网页左侧为“下载”和“下载进度”，下方为主题切换。“下载”页内切换单条/批量方式。标题保留应用名和实际后端版本，输入区采用简洁下划线与清除/粘贴按钮。画质及类型面板沿用现有下载控制器，图文不另设入口。

两端连接同一个本地服务，使用同一下载队列、配置与加密凭据。打包客户端优先启动配套核心，不再依赖仓库内的 Python 环境。关闭客户端不会结束已启动的共享托盘服务，网页下载继续运行；要结束后台服务，请使用托盘“退出后台服务”。

若发现旧后端，客户端会明确提示从旧版托盘正常退出后重连；不另起第二个核心争用相同任务文件，也不强制结束旧进程。用户配置和登录资料继续存放在 `%LOCALAPPDATA%/OmniDownloader`，不随解压目录改变。

## 开机启动

在客户端“设置 → 下载引擎与组件”管理“网页服务随 Windows 启动”，也可在此打开精简网页版。开启后只启动后台服务，不自动弹出网页或客户端。此开关已从下载设置与托盘菜单移除。

启动项使用当前 Windows 用户的单个 Run 记录，迁移旧版程序自身的两个 Startup 快捷方式，避免重复启动。只处理 OmniDownloader 自己的启动项，不删除其他程序的记录。修改失败会返回错误并恢复开关显示，不报告虚假的保存成功。测试使用模拟注册表，未替用户启用或禁用实际开机启动。

## 登录兼容修复

保留此前 Google 登录修复：普通 Edge 窗口供用户手动登录，输入凭据期间没有远程调试或 WebDriver 标记。保存时正常关闭该专用窗口，再短暂读取持久化会话；仅导出目标平台第一方 Cookie，使用 DPAPI 加密保存。

通过浏览器自己的设置接口启用该专用档案的会话恢复，不修改其保护哈希。部分已有 Edge 档案拒绝隐藏设置标签，已加入普通后台设置页的能力回退；不会因初始化失败清除已有档案。实际 Edge 测试覆盖正常登录窗口的 WebDriver=false、HttpOnly/session-only Cookie、浏览器存储重开，以及隐藏标签不支持的分支。真实 Google 账号、验证码和风控仍需用户验证，未将合成会话测试描述为真实账号验收。

## 构建与验证

在具备 Python 构建环境及 .NET/Windows App SDK 的 Windows 开发机运行：

```powershell
.venv/Scripts/python.exe tools/build_unified_windows.py
```

该脚本生成版本化目录及单个整合 ZIP，不停止现有应用，不删除旧发行目录。原有 Web/pywebview 构建脚本和移动端保持独立，未修改 Android、iOS 或 Agent Edition。

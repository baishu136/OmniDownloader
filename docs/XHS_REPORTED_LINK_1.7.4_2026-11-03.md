# Android 1.7.4：用户报错链接对照与图文兼容（2026-11-03）

## 对照结果

用户补充的分享链接最终返回笔记 `6ae92bb20000000018038a89`。页面声明 `type=normal`，含 3 张静态图片，无 video 对象、媒体视频流或 Live Photo。因此视频入口返回 NO_MEDIA 是正确的类型提示；这条具体笔记并非视频提取失败。

1.7.3 已交付的视频新状态兼容仍保留。同时实测发现图文入口独立存在两处问题：桌面请求跳到登录页；旧状态转换的贪婪匹配不能稳定读取移动分享页。新版本为小红书图文请求使用移动分享页身份，以不执行 JS 的方式转换状态并读取首个 JSON 对象，兼容旧桌面 noteDetailMap 和新移动 noteData.data.noteData，严格匹配目标笔记 ID，不递归拾取推荐内容。图文入口仍拒绝将视频笔记封面当作图文。

## 验证

- 共享 Python 35 项 pytest 通过，新增新旧结构、undefined 与后续脚本、错误 ID、视频封面、无关嵌套图片防误用回归。
- Android API35 x86_64 模拟器，使用 1.7.4 应用内实际 SharedPython、DownloadEngine 和 StorageExporter，匿名直连验证用户补充的链接。
- 实际图文解析返回 3 张图片；IMAGE 单张保存和 IMAGE_ZIP 三张归档均成功导出到系统下载目录。
- ZIP 内 3 张图片可解码：1080×1440、1080×1440、414×552；ZIP 482,731 字节，单张图片 173,284 字节。归档清单不包含签名资源 URL，测试产物已清理。
- 页面元数据前两张标记 2625×3500，但当前分享页返回的图片文件实际是 1080×1440。本轮不把这些文件声称为完整原始尺寸或已经验证无水印；保留现有来源未确认标记。
- 私有样例记录在 testdata/xhs-reported-2026-11-03.private.json，未将完整分享令牌或 HTML 快照打入安装包。

## 使用与范围

覆盖安装 release/1.7.4/OmniDownloader-1.7.4-arm64-v8a.apk，进入“图文下载”，粘贴这条链接并选择“解析图文”，然后保存所选图片或 ZIP。不需要清空应用数据。真正的视频笔记继续使用视频入口。

本轮没有连接物理手机，实际保存验收使用模拟器完成。共享 Python 源码同步用于 Windows，并已运行相关单元测试；Windows 可执行安装包本轮未重新打包，iOS 未修改。已有其他工作目录改动保留。

最低 API26、目标 API34、ARM64 ABI 沿用原配置；APK 校验值与签名在交付前单独校验。

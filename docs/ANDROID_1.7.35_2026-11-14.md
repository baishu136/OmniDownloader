# Android 1.7.35：下载传输提速与低速恢复

versionCode 94。本轮优化 Android 的媒体传输，保持既有选流、分辨率、音轨和导出流程。

## 实现

- yt-dlp 的 HLS/DASH 正常传输使用 4 路分片并发，兼容重试保持 1 路。缺少分片时停止并报告错误，避免把不完整的视频当作下载成功。直接 M3U8 先使用原生分片调度，失败后保留 FFmpeg 无损封装兼容路径；Cookie 开关、代理和请求头沿用原有策略。
- 已知长度至少 8 MiB 的直链，在服务器支持精确 Range、返回强 ETag 且暂存空间充足时使用 4 路分段。全局分段信号量上限为 4。小文件、未知长度、弱/缺失 ETag、跳转地址及不支持分段的服务器走串行流程。B 站的同一条音/视频轨也复用该分段器。
- 每个分段独立暂存，要求状态 206、起止位置、总长度、强 ETag、响应长度及媒体地址全部一致。分段全部完成后按顺序合并，随后经过既有媒体质量校验及导出。改变实体、忽略 Range、错位或截断时清除分段，重新串行下载；取消直接停止，访问拒绝或限流向上层报告。额外 Range 请求不跟随跳转，不向新地址转发捕获的请求头。
- 并发暂存需要约两倍文件大小加 64 MiB 空间；不足时采用串行下载。已有串行断点仍按串行续传，206/416 续传结果必须保持原验证器，避免拼接不同文件。并行分段不跨进程保存；中断后重新下载，保留既有串行续传能力。
- 抖音、小红书及 X 的已确认作品直链，先预热 10 秒，再观察完整 20 秒窗口；平均低于 64 KiB/s 且剩余超过 4 MiB 时触发受限恢复。只接受同一媒体 ID 且满足原选流要求的新源；抖音/小红书沿用既有候选次数上限，X 最多刷新一次。后续尝试关闭低速检测，避免反复重启。
- 无可用新源、刷新仅遇到网络或未确认响应时，可一次切回原源串行下载；明确的权限拒绝、验证码、错作品、质量不可用及限流不使用此回退。无法确认原作品的普通直链不触发自动重新解析。
- B 站只在有平台提供的备用地址时检测首个源的持续低速；备用地址必须来自同一条轨道，切源从零开始。没有备用源时保留慢速下载。
- 单次媒体源失败不会提前把仍在恢复的直链任务写为失败。批量任务仍沿用现有调度，本轮增加的是单文件内部并发，没有增加批量同时下载数。

## 验证

- 253 项 JVM 测试通过。新增覆盖分段覆盖范围、强验证器、跳转不转发 Cookie、服务器忽略 Range、实体改变、错位/截断、403/429、取消、低速检测和续传验证器。
- Android 15 x86_64 专用模拟器：2 项并行实际保存测试通过。使用带音轨的 320×180 MP4 加合法 `free` 原子，超过 9 MiB，验证分段触发、MediaStore 导出及完整文件逐字节一致；实体改变时实际重新串行下载，未导出混合字节。
- 批量后台下载、预解析完成移除、服务取消响应、仅重试导出、X 公开响应及 HLS 音轨共 14 项设备回归通过。调整后的实际保存及相关链路也已复验。
- 既有用户 X 样例 `/video/2` 实际下载通过：目标媒体 ID `2119045986412531712`，选择 `hls-1925`，选择及成品均为 720×1280，19904ms，包含音轨，4728575 字节。该样例验证选流与保存，不作为全平台速度对比；测试成品已移除。
- 受控本地基准：Windows、JDK 17，1048589 字节，每连接每 4ms 发送 8192 字节。串行 670ms，四路 189ms，峰值 4 连接，成品字节一致。约 3.5 倍仅适用于此单连接限速模型；未据此承诺平台实际提升幅度。

Release 构建通过，Lint 为 0 errors、52 warnings；新增的一项是 `usableSpace` 建议使用可回收缓存估算。这里有意按实际空闲空间保守决定是否分段，空间不足仍可串行下载。ARM64 R8 正式包启动、导航、设置子页及批量页冒烟通过。APK 沿用原签名，依赖及原生库不升级。最终结果和日志随 `release/1.7.35/qa/results.json` 保存。

## 适用范围

本轮仅交付 Android。未替换 Windows、iOS 或运行中的本机 Web，未公开发布至 GitHub。没有实体 ARM64 手机可用，正式包的模拟器 UI 冒烟跳过 ARM64 原生执行；原生下载及文件校验由 x86_64 调试安装验证。

平台总限速、服务器负载、访问权限、代理出口和设备网络仍可能成为瓶颈。低速检测覆盖上述受控直链与 B 站备用轨道，不会主动重启任意平台的 yt-dlp/HLS 下载，也不会降画质或跨作品换源。

协议参考：[HTTP Range / If-Range](https://www.rfc-editor.org/rfc/rfc9110.html#name-range)、[yt-dlp 下载选项](https://github.com/yt-dlp/yt-dlp#download-options)。

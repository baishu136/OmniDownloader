# Android 1.7.31：小红书图片与封面水印修复

versionCode 90，包含 1.7.30 的抖音解析等待优化，保留原签名和 ARM64 原生组件。

## 已定位与修复

用户样例：https://xhslink.cn/o/2abFtV1vh6x ，笔记 ID `6af2bf51000000002b0279ac`。

这条笔记的平台类型是视频，其 H5 图片/封面使用 `sns-webpic-*.xhscdn.com` 的 `!h5_1080jpg` 处理样式，图片中央额外叠加“小红书”字样。原实现缺少明确 original 字段时直接使用 `urlDefault`、`url` 或 `urlPre`，下载字节本身没有再绘制水印，但取得的源已经包含平台水印。

- 图文优先通过目标笔记的 `fileId` 定位同一图片的标准资源；旧结构可从明确的小红书图片 CDN 地址提取同一图片 ID。保持资源顺序和选择 ID，不借用推荐内容或其他图片。
- Android 原生视频封面、通用解析封面和独立封面保存也使用相同的标准图片源。
- 下载时重新检查旧缓存/已建任务中的 H5 地址，避免更新后继续保存旧水印资源。无法定位标准资源时明确失败；标准源请求失败时不自动退回带水印预览图。
- 图片仍直接保存服务器返回的字节，不修改画面、裁剪或重绘；原图自身的文字和作者标记保留。标准 JPEG 资源不冒充上传原件，来源记作 PLATFORM_SOURCE；存在明确原图字段或已经给出的标准地址时保留来源信息与原格式参数。
- 只识别指定第一方图片 CDN 和受约束的资源 ID。未知域名、带凭据地址和路径穿越输入不能被改写为标准图片请求。
- 共享解析器重新打包到 Android Python 依赖资源，附带 SHA-256；本轮没有升级第三方库或原生处理组件。

接口形式参考：[XHS-Downloader 源码](https://github.com/JoeanAmier/XHS-Downloader/blob/master/static/XHS-Downloader.js)。本次结果以该用户链接的第一方响应、实际图片对比和生产下载链路为依据。

## 调试记录

- 根因：把平台加水印的 H5 展示资源直接当作可保存图片；旧快照和封面路径也保留该地址。
- 修复：按同一笔记图片 ID 取标准资源，并在解析、旧任务下载与封面保存三处统一选择；对无法确认的 H5 来源明确失败。
- 证据：旧资源和标准资源尺寸一致、画面不同；三种 Android 保存路径得到标准资源的完全相同字节。
- 状态：DONE_WITH_CONCERNS。平台源可能失效或受访问限制，不承诺删除作者嵌入原图的内容；实体手机和启动冒烟首次可见性失败情况如上。

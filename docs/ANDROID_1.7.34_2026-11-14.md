# Android 1.7.34：X 公开解析误判与回退中断修复

versionCode 93。针对用户反馈的 `[MEDIA_ID_MISMATCH] 公开接口未确认原帖子` 调查并修复 Android 解析链路；保留拒绝其他帖子的保护。

## 排查结论

报错来自 `XPublicExtractor` 的根级帖子 ID 检查。此前逻辑直接比较返回 ID 与请求 ID，空 JSON、缺少 ID 或空 `id_str` 都会被归为“其他帖子”。`DownloadEngine` 又将这个错误作为不可回退条件，导致原生公开接口的一次空响应终止后续独立传输路径。

确认三个可复现的流程问题：

1. 缺少身份数据被当成身份冲突。旧实现对 `{}` 返回用户所见的 MEDIA_ID_MISMATCH；缺失身份实际上没有证明返回了另一条帖子。
2. 上游直接报告 `Syndication endpoint returned empty JSON response` 时，不在本地回退触发条件中，尚未进入公开适配器就中断。上游也将空 JSON 单独处理，见 [yt-dlp Twitter 提取器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/twitter.py)。
3. `id_str` 存在但为空时，没有使用同一响应根级的有效 `id`，会误拒绝能够精确确认的目标响应。不能通过浮点数近似恢复长 ID，也不能拿引用帖的 ID 充当根级 ID。

共享解析器原本对明确的其他根级 ID 也报 MEDIA_UNCONFIRMED，与 Android 原生含义不一致；本轮同步统一其身份判断和有限重试。

没有反馈用户的具体链接，无法确认其实际返回了哪一种响应，也无法断言这些缺陷是此次反馈的唯一原因。调查使用现有用户样例与可控制的响应测试，不把其他正常样例当作反馈用户原帖已经修复的证明。

## 修复行为

- 没有可精确确认的根级 ID：MEDIA_UNCONFIRMED。最多取得两次响应；第二次加 `Cache-Control: no-cache`，不以推荐内容、引用帖或递归搜索结果替代目标。
- 返回明确不同的根级帖子 ID：MEDIA_ID_MISMATCH，一次即停止，不重试，不继续另一条传输路径。
- 同一响应的 `id_str` 为空或 null，可使用精确的根级 `id`；有明确不同的 `id_str` 时不能用其他字段覆盖冲突。Android JSON Long 保留 19 位数字；科学计数法/浮点近似不能确认身份。
- 主提取器的空响应、未确认媒体、适配结构变化及既有网络错误可尝试公开适配器。权限拒绝、需要验证及明确身份冲突保持停止条件；公开接口本身限流或拒绝访问时不继续回退。
- 原生公开路径的两次响应与 JS 签名运行共享 35 秒总预算，不是每次请求各等待 35 秒。共享 Python 公开请求每次 socket timeout 为 12 秒、extractor retries 为 0，空身份最多显式请求两次。此预算只指公开适配器，主提取器及后续路径另有既有上限。
- 公开请求继续使用独立、无账号 Cookie 的客户端；没有新增第三方解析服务。独立传输路径取得的新响应也必须重新通过根级 ID 校验。
- 没有更改媒体 ID 生成、多视频的原始位置索引、已建下载任务、清晰度选择或 HLS 配套音轨保存方式。
- 共享解析器重新打包至 Android extras，压缩包内只有 `omni_media.py` 改变，依赖版本和其他条目不变。本轮未替换 Windows/iOS 安装包或运行中的本机 Web。

## 验证证据

- 修复前：239 项 JVM 测试中新增回归失败 6 项；共享引擎新增回归失败 8 项。覆盖缺失身份、暂时空响应后恢复、重复空响应边界、空字符串 ID 回退及明确错帖停止。
- 修复后：239 项 JVM 单元测试、共享引擎全量 91 项测试通过。
- Android 15 x86_64 专用模拟器：8 项响应/HLS 设备测试通过，直接调用生产响应确认方法，验证精确 Long ID、null/空 ID、引用帖不作为根 ID、浮点数不能近似确认、显式拒绝不重试，以及 HLS 配套音轨不丢失。
- 既有样例 `https://x.com/whyyoutouzhele/status/2119233448888217846` 的公开接口实测 HTTP 200、根级 ID 正确，媒体数组包含 3 个视频和 1 张图片。

- ARM64 R8 Release 包启动/导航/设置子页/批量页冒烟通过；该模拟器冒烟跳过 ARM64 原生代码，未进行实体 ARM64 手机验收。
- Release 构建通过，Lint：0 errors、51 warnings；延续原签名。

## 调试记录与后续定位

状态：DONE_WITH_CONCERNS。已确认并修复可复现的流程问题，未知反馈原帖与实体手机场景仍未验证。

本次持久经验：外部响应的“身份缺失”与“明确身份冲突”必须使用不同错误语义，否则硬性防串帖保护会误中断可恢复请求。有限恢复只能重新取得并独立确认目标身份，不能放松 ID 比对。

若仍有同样下载失败，需具体链接与错误码区分目标内容权限、公开接口未提供媒体、限流、网络和真实错帖。未取得链接之前，不把所有失败归因为登录，也不承诺所有 X 内容均可匿名下载。

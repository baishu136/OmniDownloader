# Android 1.7.44：图片加载与缓存优化

versionCode 103。仅交付 Android ARM64 安装包，未公开发布 GitHub，未替换本机 Web、Windows 或 iOS 安装包。

## 改动

- Pixiv 作品和画师图片保留接口提供的预览地址，列表优先使用同一作品、同一页、同一来源主机的预览图。预览地址独立存储，下载和大图查看继续使用原图地址。旧版图文记录缺少预览字段时继续兼容。
- X 列表使用 small 图片；支持的 Pinterest、哔哩哔哩 CDN 使用较小的列表/封面图片。无法确认的地址不改写，保留签名参数和原始下载资源。
- 内存、磁盘缓存使用稳定的平台会话代际、URL、Referer、Cookie、代理配置哈希，不再为每次进入页面生成随机内存键。相同凭据重新进入可复用缓存，不同凭据分开缓存；缓存键不含明文 Cookie 或代理密码。
- 图文列表在后台解密一次会话快照，再逐 URL 匹配域名、路径、HTTPS、过期及 Cookie 开关。并发构造同一图片请求只执行一次 Cookie 工作。会话或代理改变后重新建立请求作用域。
- 打开原图时复用已加载的列表图作为内存占位，原图完成后替换。图片查看器保留缩放和 GIF/WebP 动画解码，原图禁用 RGB565；列表继续按最大 640×640 静态解码，避免滚动时同时播放大量动图。
- 图片加载遵循应用代理，独立限制为总计 8、单主机 4 个并发请求，连接超时 12 秒、读取超时 25 秒；保留 X/Pixiv 请求保护。图片磁盘缓存上限由 50 MiB 调整到 128 MiB，仍由缓存自动淘汰，不影响下载文件。

## 验证

- 285 项 JVM、140 项 Python 测试通过。
- Android 15 x86_64 模拟器 18 项相关回归通过：缓存复用、账号隔离、并发请求构造、Cookie 域和路径限制、160 张图片列表静态预览、640 像素解码上限、查看器原始 GIF 播放、选择与布局、X/Pixiv 原有保护。
- 本地测试服务器人为延迟 400ms，64×64 PNG：首次网络加载 819ms，重新创建图文请求缓存后读取内存约 2ms；清空内存后命中磁盘。相同账号的这些访问总计只发 1 次网络请求，切换合成账号后新增 1 次。此为受控缓存测试，不代表各平台实际网络加速幅度。
- 160 张 GIF 列表测试中，已加载的列表结果均为静态解码；打开查看器后确认可播放原始动图。原图下载地址及存储流程未改为缩略图。
- 正式包构建、Lint、签名校验及 R8 UI 冒烟结果随交付保存在 qa 目录。原生运行时和 Python 第三方依赖保持不变，共享解析模块只新增可选预览字段。

未验证实体 ARM64 手机和各平台真实网络速度。ARM64 正式包在模拟器中验证界面和资源解压，原生/图片行为回归使用 x86_64 测试包。本轮未操作真实账号。

# Android 1.7.29

仅 Android，versionCode 88。

批量解析默认最多两路并行；同一平台（包括其短链）依次解析，通用站点按不区分大小写的主机名归组，其他平台可以同时处理。页面和持久化记录保留输入顺序，单条失败不阻塞其他链接。并发状态与加密保存统一加锁，入队任务额度原子预留，仍限制每批 100 条链接、最多 500 个任务。停止时取消所有活动解析进程，已入队的下载继续执行；重启后的未完成条目仍可继续，重试沿用稳定任务 ID。

智能识别支持无换行拼接的分享链接，保留签名查询参数与 `=https://...` 形式的原始跳转参数，自动去重。逐条模式继续拒绝一次添加多条链接。

批次处理记录标题旁新增“清空记录”，确认后删除加密批次记录；保留已填链接、下载任务和文件。解析期间禁用，避免解析完成后重新写回已清除的记录。清空输入与清空记录仍是独立操作。

修复了真实多链接测试中暴露的下载服务锁问题：之前在服务锁内以 `UNDISPATCHED` 启动下一任务，IO 线程可能直接进行阻塞网络读取，主线程执行服务命令时无法取得锁。现在先以 LAZY 创建并登记工作协程、注册完成回调，再调度启动；完成回调同时处理尚未进入协程体即被取消的情况。网络工作不在服务锁内执行，保留代次与任务标识校验，防止迟到更新覆盖已取消状态。

可控本地 MP4 下载后接一个阻塞 HTTP 源，在旧实现中稳定出现主线程 BLOCKED 于 `DownloadService.onStartCommand`，网络线程栈同时包含 `processNextTask` 和 `RealCall.execute`，取消命令与 UI 心跳均无法完成。新增 `DownloadServiceQueueTest` 先在旧代码上验证失败，再在修复代码上通过。新旧日志和线程栈见 qa。

协程行为参考：[Kotlin UNDISPATCHED 官方说明](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/-coroutine-start/-u-n-d-i-s-p-a-t-c-h-e-d/)。本地线程栈和回归测试是本次故障判断的直接证据。

真实样例还触发 YouTube 选流探测的临时文件错误：即便 TMPDIR 已设为应用缓存，yt-dlp 的格式探测仍会使用默认相对目录，进程工作目录为 `/` 时写入 `/tmp*.tmp` 而失败。下载请求现在显式指定当前任务的私有 staging 目录为 `--paths temp:`，安全通道重试也通过同一工厂继承。离线格式探测使用同一 Android Python/yt-dlp 运行时与 localhost MP4，旧参数稳定报只读文件系统，新增参数后探测和完整下载均成功。没有更换引擎或关闭选流校验。

前三组/第四组初次测试均发现同一 YouTube 临时目录错误。修正后通过生产重试入口按原任务 ID 续测，保留首次错误和后续状态。完整 HLS 传输采用保留原选流的断点续传；测试等待上限曾由 20 分钟调为 2 小时，初期测试超时单独记在 earlierRetestDeadlineExceeded，不能作为下载成功。

DEBUG REPORT

- 症状：上一下载完成后，下一个阻塞网络源令主线程无法处理取消命令；YouTube 选流探测试图写只读根目录。
- 根因：服务锁内 UNDISPATCHED 启动网络工作；默认临时路径随当前目录解析。
- 修复：LAZY 登记与完成回调后调度工作；下载请求明确传入各任务的私有临时路径。
- 证据：服务锁回归在旧代码上失败，线程栈为 main BLOCKED / 网络线程持有调度调用栈；修复后 5 项设备回归通过。原生选流临时路径离线探测旧参数失败、新参数成功，公开样例重试结果见上表。
- 状态：DONE_WITH_CONCERNS，平台会话限制及 ARM64 真机验收缺口如实保留。

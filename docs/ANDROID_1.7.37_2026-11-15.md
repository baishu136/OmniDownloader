# Android 1.7.37：多图滚动优化与回到顶部

versionCode 96。针对多张图片结果页滚动卡顿，优化列表图片请求和解码，并增加右下角回到顶部按钮。

## 修改

- 列表使用最大 640×640、按比例缩放的静态预览；GIF/WebP 不在列表中同时播放。X 图片优先使用同一媒体的 `name=small` 预览地址。全屏预览仍请求原地址并保留动图播放、缩放和保存，下载资源与原图尺寸元数据不变。
- 图片请求按作品及账号状态缓存，最多保留 160 个请求对象。Cookie 读取、解密和请求构建移到 IO 线程，返回附近图片及更新选择时复用已有请求。缩略图与全屏预览使用独立内存缓存键，避免静态预览替代原图或动图。
- 已知尺寸时忽略解码取整造成的轻微比例差异；缺失尺寸或方向明显不符时只修正一次。首页图片行设置统一内容类型，减少滚动时的重复布局工作。
- 全选、清空选择、ZIP 和保存功能区完全滚出视野后，在内容区右下角显示「回到顶部」，位于底部导航栏上方。点击返回首页顶部后自动隐藏。长列表先定位到顶部附近再短距离滚动，避免逐行穿过整份图库；滚动位置由独立组合范围中的 `derivedStateOf` 观察，不逐像素重组整个首页。
- 保留原有多列排版、图片预览与留白选择行为、按帖 ZIP、选择状态及原图下载功能。

## 排查与证据

按 investigate 的根因排查流程，先保留 1.7.36 生产代码添加回归用例，再实施修复。代码确认原先每张图片进入视口时都会构造请求，并在 UI 线程执行 `SessionRepository.cookieHeader`，该方法包含会话解密、JSON/Netscape Cookie 解析及过滤；列表和查看器共用原图请求，默认动图解码器会创建可播放 Drawable。

Android 15 x86_64 专用模拟器，本地 HTTP 服务提供 160 个不同图片地址、每个返回既有 16×16 双帧 GIF，连续五次 250ms 上滑。修复前记录 86 个加载结果全部为可播放动图，新增的静态预览断言失败；修复后同一用例记录 84 个加载结果、可播放列表动图为 0。加载结果数量受列表预取和设备调度影响，不能将其差异当作网络请求减少比例，也不是 FPS 对比。

设备用例另行实际解码 4096×3072 PNG，确认列表位图长宽均不超过 640；通过从 Main dispatcher 调用请求工厂并断言 Cookie 回调不在主线程，验证工作线程边界。重复请求返回同一对象，原图地址和解码器策略保留，账号缓存作用域隔离，超过容量后旧请求被淘汰。

- 261 项 JVM 单元测试通过。
- 9 项设备测试通过：160 图滚动、静态/原图动图分离、回顶显示/点击/隐藏、Cookie 线程与缓存、大图解码，以及原有图文排版、留白/复选框选择、窄屏大字体、首页共享输入框和 X 分页选择保留。最终测试截图随本地 QA 保存。
- Release 构建及 Lint 通过，0 errors、52 warnings；沿用原签名。正式包启动/导航冒烟结果随 `qa/results.json` 记录。Python extras、下载引擎依赖及原生库未改变。

状态：DONE_WITH_CONCERNS。已复现并消除上述可验证的图片列表负担；尚无实体 ARM64 手机进行滚动帧率验收，不能承诺所有设备完全没有掉帧。正式包在模拟器上的 UI 冒烟跳过 ARM64 原生执行，实际图片加载验证使用 x86_64 调试安装。本轮未公开发布至 GitHub。

持久经验：列表图片请求应在账号作用域内复用；不要在 Lazy 列表单元构建期间同步解密会话。静态缩略图和全屏动图需分开请求及内存缓存键，否则两种展示方式可能相互复用不合适的 Drawable。Coil 默认已按约束采样，不能未经验证就把原先所有卡顿归因于“全尺寸位图”。

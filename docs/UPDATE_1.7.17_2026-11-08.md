# OmniDownloader Android 1.7.17

修复 X 同一帖子包含多个视频时，报“合集没有返回可定位的分集链接”的问题。

部分 yt-dlp 合并格式结果只包含每个视频的真实媒体 ID 和 formats，所有视频共用帖子地址，没有顶层 url 或 /video/N 地址。此前解析器会跳过这些有效条目。现在保留原帖子地址，以每个视频自身的媒体 ID 和完整格式快照定位下载，兼容分离的 HLS 音视频流。

同帖视频快照按媒体 ID 分开存储，避免最后一个视频覆盖前面的视频。不会按照过滤后的视频列表序号虚构 /video/N，避免图片与视频混排时错选。保留明确指定视频序号的行为，同时规范化 twitter.com 别名和分享跟踪参数。

用户提供的帖子 `https://x.com/whyyoutouzhele/status/2119233448888217846` 已在 Android 15 x86_64 隔离模拟器中完整实测下载，结果如下：

| 视频 | 真实媒体 ID | 成品尺寸 | 时长 | 音轨 | 文件字节数 |
| --- | --- | --- | --- | --- | --- |
| 1 | 2119045986353926144 | 360×512 | 130.473 秒 | 有 | 4,676,687 |
| 2 | 2119045986412531712 | 720×1280 | 19.904 秒 | 有 | 4,728,575 |
| 3 | 2119045986395791360 | 180×278 | 31.231 秒 | 有 | 648,785 |

三个文件的 SHA-256 均不同；第二个视频使用 HLS 视频轨与独立音轨合并。实测使用开发机 HTTP 代理和与模拟器架构相符的调试包，没有使用账户 Cookie。上表是这次返回并下载的实际尺寸，不表示每个视频应具有相同画质。

162 项 JVM 测试、10 项 Android 回归测试及 1 项真实多视频下载验收通过。回归覆盖缺少顶层地址、同帖快照互不覆盖、错误媒体 ID 拒绝、twitter.com 别名、HLS 音轨及上一版本 GIF 修复。JVM 检查首次遇到既有 HTTPS 代理测试的 Socket closed 竞态；最终复跑 162 项全部通过，该代理代码本次未修改。

安装包：`release/1.7.17/OmniDownloader-1.7.17-arm64-v8a.apk`，版本代码 76，沿用现有签名及 Android 8.0 以上、ARM64 支持范围，包含 1.7.16 的画质和 GIF 修复。升级后请重新解析该帖子，再勾选需要的视频下载。

Release 构建、静态检查（0 个错误、46 个警告）、签名和 APK CRC 检查通过。压缩后的 ARM64 安装包在隔离模拟器完成冷安装、历史记录恢复、导航和设置子页检查；该检查跳过 ARM64 原生程序执行。

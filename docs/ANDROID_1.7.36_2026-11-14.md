# Android 1.7.36：X 博主主页图片解析

versionCode 95。首页填入 `https://x.com/hazzi_808` 这样的博主主页，点击「立即解析」，即可分页读取该博主当前可访问的图片帖子。支持 x.com、twitter.com 的主域、www/mobile 地址及 `/media` 路径；帖子、系统页面和相似恶意域名不会误识别成主页。

## 功能与边界

- 主页直接进入图片解析，共用原首页输入框，不先尝试视频提取器。逐页累计结果、显示图片帖子数和图片数，保留平台提供的原图尺寸及原图地址。
- 从平台照片时间线读取，仅接受已确认用户 ID 对应帖子自己的 `photo` 媒体；不采集头像、视频/GIF 封面、广告、转发或引用帖图片。不通过递归遍历引用/推荐数据补图。重复图片 ID 与原图地址去重，保持首次出现的顺序。
- 页面有下一页游标时继续解析，即使该页没有可保存图片也不提前结束。缺少时间线、未知结构、重复游标或身份冲突返回明确错误。只有有效页返回末页条件时显示「平台已返回末页」，该状态不代表平台保证提供了全部历史或无权限帖子。
- 可停止后继续；后续页不会恢复用户已经取消选择的图片。中途失败保留最近确认页的结果和游标。一次运行最多读取 100 页，超大主页可点击「继续解析」。这些扫描结果保存在当前应用会话内，重启应用后需重新扫描；首页链接草稿及已经生成的下载任务继续沿用原有持久化。
- 支持单张保存或按帖子生成独立 ZIP。下载任务持久化为普通 `/status/<id>` 链接及稳定图片 ID，不把整份主页当成一个帖子。缓存过期后只需重新核验对应原帖，无需重新扫描主页。图片保存目录沿用设置中的图文目录。
- 批量页也识别主页；完成分页后按图片帖子创建 ZIP 任务，受既有每批 500 个任务限制。若达到单轮分页上限，批量页明确报告尚未完成，不把部分扫描结果作为全量入队；超大主页可在首页继续并选择保存。
- 复用设置—账号中的 X Cookie 开关与会话。支持仅主域 `x.com` 和旧 `twitter.com` 登录 Cookie 导入，仅将平台根域的 `auth_token`、`ct0` 放入该次 X 适配器的内存 CookieJar；不会修改导入文件、保存账号密码或把其他域 Cookie 转发给 X。临时会话文件沿用现有请求作用域并在结束后清理。
- 主页与单帖公开接口不同，平台可能要求有效登录会话。匿名受限时显示 AUTH_REQUIRED 及「管理 X Cookie」入口；访问限制、验证码、限流和接口变化均不会伪装成“没有图片”或“已全部解析”。更换账号/代理后重新解析，避免把不同请求作用域的分页结果拼接。

## 实现与验证

X 请求使用固定版本 `gallery-dl 1.32.20` 的照片时间线操作、请求参数及交易签名，应用自行负责单页读取、身份确认、图片筛选、去重及完成判定。仅增加该纯 Python 依赖，许可证随 Android extras 打包；已有依赖条目除 `omni_media.py` 外字节不变，未升级原生库。正式 APK 较 1.7.35 增加约 0.8 MiB。

- 261 项 JVM 测试通过：主页路由、域名/路径约束、多页去重、原帖任务规划、空图片页继续、失败后续页恢复、单轮上限及取消不发布迟到结果。
- 114 项共享引擎测试通过：时间线与媒体模块解析、原图选择、作者/帖子 ID 冲突、封面/引用/转发排除、明确末页与重复游标、分页请求约束，以及主域/旧域 Cookie 的安全归一化。
- Android 15 x86_64 模拟器 12 项设备测试通过：内置 Python 3.12 实际导入并运行固定版本适配器，执行两页受控数据解析并规划原帖；界面翻页后保留取消选择、停止后保留结果/继续入口；以及首页布局、批量完成移除和 X 公开响应回归。
- 示例 `https://x.com/hazzi_808` 已分别通过开发环境及 Android 生产解析入口请求：匿名访问均返回 AUTH_REQUIRED，未报告全量解析成功。没有该主页的有效登录会话，因此未进行登录后的真实全量抓取验收；受控分页测试不能替代这项验证。
- Release 构建、Lint、原签名及 R8 正式包冒烟结果见本地交付 `qa/results.json` 和日志。实体 ARM64 手机尚未验收，正式包的模拟器冒烟跳过 ARM64 原生执行，原生 Python 路径由 x86_64 调试安装验证。

本轮交付 Android，保留已有的下载提速、图文、GIF 和批量功能。未更换运行中的本机 Web、Windows 或 iOS 安装包，未公开发布至 GitHub。

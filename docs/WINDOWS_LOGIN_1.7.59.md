# Windows 1.7.59：登录会话捕获与保存

本次针对桌面版和本地 Web 版共同的登录问题，重点修复 Google 登录结束后没有目标平台 Cookie、浏览器与下载核心状态分离，以及保存状态误报。

## 使用

1. 启动 1.7.59 后端及对应界面，在「设置 → 账号」选择平台。
2. 点击「浏览器登录」，在应用专用的 Edge Profile 中登录。Google 登录跳转可以打开新标签或窗口；完成后请回到 YouTube 或原目标平台。
3. 点击「保存会话并关闭」。成功响应在凭据原子落盘、登录浏览器关闭后返回。YouTube 在 Google 中转页面没有目标平台登录标记时会拒绝保存，保留原凭据。
4. 重新解析原链接，确认实际账号与内容权限。界面的「已保存」没有冒充平台账号验证。

Web 与旧 pywebview 桌面版使用同一网页入口；WinUI 3 账号页也接入相同后端接口。使用旧后端无法提供新接口，需要先启动新版本后端。若旧版占用 58000，新 Web EXE 会按原有单实例规则连接旧服务；升级时应先正常退出旧版托盘。

## 实现与边界

- `windows/core/browser_login.py`：使用真实 Edge 和浏览器级 CDP，独立 Profile 保存 Google SSO、Cookie 及浏览器存储；仅向凭据库导出选中平台域内的 Cookie。没有读取用户日常 Edge Profile。
- 浏览器级捕获不依赖当前活动页面，支持登录跳转和弹窗。没有使用 `document.cookie`，因此可以读取 HttpOnly Cookie。
- Profile 以稳定域名标识保存在用户状态目录的 `login-profiles/`，不在 EXE 安装目录中。浏览器窗口关闭、升级和下载缓存清理不会删除 Profile。
- `SessionStore` 保留现有加密文件位置，兼容旧数据；修复 HttpOnly 标记丢失，添加跨进程锁、唯一临时文件、原子替换和过期/损坏检测。
- 成功完成的 yt-dlp 调用可以回写更新的临时 Cookie 文件。写回有版本检查；导入新账号、停用或清除会话后，旧任务无法恢复旧凭据。其他原生 HTTP 解析器的响应 Cookie 刷新尚未统一回写。
- 清除会话先使旧版本失效，再关闭对应登录浏览器并删除此平台的受控 Profile。校验目录边界，清理失败不会报告成功。
- 管理接口仅允许本机地址和同源请求，拒绝非本机 Host。Cookie 值、Google 凭据、带参数的登录 URL 均不返回到普通接口。
- 分区 Cookie 无法完整映射到普通 HTTP CookieJar，明确跳过并报告数量；依赖该能力的登录不宣称支持。平台真实失效、验证码、风控、会员及 YouTube PO Token 等限制仍然适用。
- YouTube 自动捕获基于第一方登录 Cookie 标记，不是服务端账号验证。保存关闭浏览器后再下载，以减少浏览器活动引起的 Cookie 轮换。

## 接口

所有路径中的平台名称需要 URL 编码，接口共用现有本机来源检查。

| 方法与路径 | 行为 |
| --- | --- |
| POST `/api/sessions/{platform}/login` | 异步打开独立登录浏览器 |
| GET `/api/sessions/{platform}/login` | 返回阶段、运行状态、捕获时间、Cookie 数量和安全错误代码 |
| POST `/api/sessions/{platform}/capture` | 确认捕获、保存并关闭，最长等待 15 秒 |
| DELETE `/api/sessions/{platform}` | 清除核心凭据及该平台独立浏览器状态 |
| POST `/api/sessions` | 兼容已有 Netscape 文件导入 |

## 验证

新增 11 项测试覆盖：Google 中转 Cookie 不覆盖原会话、返回目标平台后的保存、HttpOnly 保留、浏览器关闭重开、自动捕获后先关闭窗口仍能幂等确认保存、刷新回写、退出后旧任务不能恢复凭据、其他窗口导入冲突、无效导入保留旧数据、过期/损坏状态、分区及外域过滤、本机访问边界和目录逃逸。

其中真实 Edge 集成测试使用全新测试 Profile 和模拟 Cookie：通过原生 CDP 写入、关闭整个浏览器、重开并读取，Google 域数据仍保留在浏览器内，导出的目标平台 Cookie 不包含 Google 域凭据。**该测试没有登录真实 Google/YouTube 账号，也不代表真实平台下载已验收。**

后端测试、WinUI 测试和构建的最终日志位于 `.local/windows-login-*.log`。真实 Google/YouTube 账号、其他平台账号、会员内容、代理环境和企业浏览器策略仍需实际账号验收。

最终后端测试为 **113 passed**（5 条现有 Pydantic 弃用警告）；WinUI Core 为 **15 passed**，WinUI 自包含发布成功。Web、pywebview 桌面版及 WinUI 均已生成构建产物。

实际便携 EXE 在隔离数据目录运行：Web 导入模拟凭据 → 退出进程 → 重启读回 → 桌面版读取同一份凭据 → 桌面清除 → Web 看到已清除，全部通过；两种 EXE 均拒绝跨站登录管理请求。记录在 `.local/windows-login-packaged-validation.json`。Web 账号页控件及未打开登录窗口时拒绝保存已实测；WinUI 已启动到原生窗口，但窗口持续处于最小化，未完成原生账号页的 UI 点击验收。

## 安装状态

发行包位于 `windows/release/`，独立可执行目录位于 `windows/dist/1.7.59/`。新包需完整解压并保留依赖目录。

尝试替换本机正在运行的旧 Web 服务时，自动审批拒绝了停止服务并替换安装目录的命令，未提供具体理由。已核实旧进程和旧目录保持原样；本次没有把旧服务更新成功记入验收。使用新版前，请先正常退出旧版托盘，再启动新包，刷新原来的网页。用户状态目录沿用原位置，首次 Google 登录请使用新版的专用入口。

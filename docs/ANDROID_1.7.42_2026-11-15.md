# Android 1.7.42：X 请求保护与独立 Google 登录档案

versionCode 101。仅交付 Android ARM64 安装包，未公开发布 GitHub，也未替换本机 Web。

## 使用

设置—账号（Cookie 页面）新增「Google 登录档案」。先添加档案名称或邮箱备注，打开档案，在其中登录一个 Google 账号；每个账号使用一个档案。名称是用户备注，不代表应用已核验邮箱身份。Google 登录完成后可点击平台登录入口，完成该平台登录，再明确点击「保存平台下载凭据」。应用仍按平台使用最近明确保存的下载凭据，不会自动轮换账号。

可退出当前档案，或勾选一个、多个档案并确认退出。退出会关闭所选档案的浏览器及 OAuth 弹窗，清除其中的 Cookie 和网站存储，并清理仍属于这些档案的本机下载凭据。其他档案后来保存或用户另行导入的凭据，即使 Cookie 内容相同，也不会被误删。清理遇到错误时保留待清理状态，可重试；旧页面迟到的保存回调不能重新导入已退出档案的凭据。

档案使用 Android WebView 独立 Profile，资料索引和下载 Cookie 以 Android Keystore 管理的 AES/GCM 加密保存。需要支持 MULTI_PROFILE 的 Android System WebView；不支持时提示更新，保留原有手动管理入口。已有共享浏览器登录无法可靠按邮箱拆分，因此不自动迁移。旧版「清除会话」及 Google 手动管理提示继续保留。

这里的退出作用于本应用独立档案，不会删除手机系统 Google 账号，也不撤销 Google 服务端的授权。已经保存在其他共享浏览器中的登录状态仍由用户手动管理。

## X 请求保护

原生解析、媒体和封面下载、图片预览、yt-dlp、gallery-dl 共用应用私有目录中的持久化预算及跨进程文件锁。默认 API 请求至少间隔 2 秒，原图/缩略图请求至少间隔 1 秒，视频媒体请求至少间隔 250 毫秒，所有通道还有 250 毫秒公共间隔。正常缓存命中不增加平台请求。

识别 HTTP 429、API 身份拒绝、登录/验证跳转、部分 HTTP 200 的 X 错误码，以及服务端限流响应头。触发后采用 15/30/60 分钟递增冷却，并服从更长的 Retry-After 或 x-rate-limit-reset；重启、切换账号、公开接口或代理不会重置。CDN 签名过期产生的普通 403 与账号拒绝分开处理。遇到限流或验证后停止切换公开接口重试，保留已解析结果。

实际 yt-dlp CLI 在 X 任务前完成一次离线保护自检；下载使用原生 HTTP/HLS，外部网络下载器回退会被阻止，避免绕过共享预算。FFmpeg 继续用于本地合成和转换。这些间隔是应用的保守策略，不是平台公布的安全阈值，也不能保证账号不会受限制。

- 279 项 JVM 测试通过，136 项 Python 测试通过。
- Android 15 x86_64 模拟器：19 项相关回归及 5 项会话回归通过。覆盖实际 CLI 插件加载、跨进程共享冷却与零额外代理连接、Pixiv 原有跨进程保护、合成账号 Cookie 隔离、单选/多选退出、凭据归属、加密落盘、OAuth 子窗口使用同一独立档案、显式保存、旧版手动流程。
- 正式包构建、Lint、同签名校验和 R8 正式包 UI 冒烟结果保存在交付目录 qa 中。原生运行时及既有 Python 第三方依赖保持不变；共享 Python 新保护仅在 Android 私有配置或明确环境变量启用。
- 没有真实 Google 账号可供操作，未验证线上 OAuth 的完整登录流程；未使用实体 ARM64 手机。正式 ARM64 包在模拟器中仅执行 UI 冒烟，跳过原生执行；原生引擎回归使用 x86_64 测试包。

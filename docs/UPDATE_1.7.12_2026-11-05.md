# OmniDownloader Android 1.7.12

## 使用变化

- 修复部分 X 视频明明存在所选画质，却报“所选清晰度当前不可用”、无法下载的问题。
- 保留分离画面的配套音轨，按原来选择的画质下载并合并声音；不通过自动降低画质或忽略音轨解决错误。

## 原因与样例验证

用户提供帖子 `2118242069319712933`，对应视频媒体 ID `2118242027599269888`。官方公开接口提供 MP4，以及分离音画的 HLS。Android 备用公开解析器此前筛掉了所有 `vcodec=none` 的 HLS 音轨，快照中只剩静音画面和其他 MP4 格式；用户选择 `hls-771` 时，下载计划 `hls-771+bestaudio` 无法找到配套音轨，从而报格式不可用。

在 API 35 x86_64 模拟器、相同目标作品、相同备用原生解析与生产下载链路上，修改前复现了用户的原始错误，ID 与错误内容一致、HLS 音轨数量为 0。修改后保留 3 个真实音轨，仍选择 **hls-771 / 720×1280**，实际下载并导出的文件为 **720×1280、9,497ms、含音轨、922,756 字节**，通过所选尺寸、时长和音轨校验，测试导出文件已清理。

本次验证直接访问官方公开接口与实际媒体源，没有重放页面响应，没有使用用户账号 Cookie，也没有把失败替换为其他作品。测试经本机既有系统代理的临时模拟器桥接完成，结束后移除桥接并恢复应用设置。

## 验证与交付

- Android 1.7.12 / versionCode 71，仅修改备用公开解析器的 HLS 格式保留逻辑、版本及相关测试；未修改 Windows、iOS、共享 Python 归档或无关模块。
- 120 项 JVM 测试通过。
- 2 项新增 Android 原生格式回归通过：分离音轨随画面保留、缺失音频编码名按未知编码保留音轨身份、原输入不被修改、已知编码及合流格式不变。
- 1 项真实接口到 HLS 下载、音画合并、MediaStore 导出和成品校验通过；所选画面格式与修改前一致。
- 初始测试曾因根帖子与 `/video/1` 的标识比较不当提前失败，修正测试比较方式后复现原始缺陷；修复后的首轮因网络未枚举出 HLS 而未进入下载，下一轮成功取得音轨并完成下载。初始及最终记录保留在忽略提交的 `.local/1.7.12/`，没有作为成功记录覆盖。
- ARM64 Release 构建、R8、lintVital、版本/ABI、ZIP CRC、v2 签名及 SHA-256 校验通过；签名与 1.7.11 一致，随包 Python 归档未变，构建前后冻结输入一致。详细结果见 `TEST_RESULTS_1.7.12.json`。
- 未进行实体手机验收，未公开发布或推送 GitHub。仅对用户提供的样例完成实际下载验证，不承诺所有受登录、权限、限流或失效资源影响的 X 链接均可下载。

安装包：`release/1.7.12/OmniDownloader-1.7.12-arm64-v8a.apk`，校验值见 `SHA256SUMS-1.7.12.txt`。安装后重新解析原链接再选择画质下载。

# Android 1.7.3 小红书视频解析修复（2026-11-03）

## 原因与修复

此前保存的小红书视频主、备用链接均可复现同类故障。移动分享页的 `window.__INITIAL_STATE__` 将目标笔记放在 `noteData.data.noteData`，旧实现仅读取桌面结构 `note.noteDetailMap[id].note`。取不到目标笔记后，旧代码将空视频流报成 NO_MEDIA；上层收到该错误立即终止，没有继续通用引擎。

新增纯 Kotlin XiaohongshuNoteParser，兼容上述两种结构，按目标笔记 ID 精确定位。旧桌面结构允许映射键提供 ID，但若正文也有 ID 则必须一致；移动结构要求正文 noteId 匹配。移除寻找任意第一个视频和全页面 masterUrl / originVideoKey 的旧辅助代码，避免误用其他笔记或推荐流。

状态提取采用字符串感知的括号匹配，容忍 JSON 对象后的其他脚本；只将引号外的 JS undefined 转为空值，保留标题、URL 和描述中的同名字样，不执行远程 JavaScript。

提取所有实际返回的编码及主、备用地址，保留尺寸、帧率、编解码和时长，继续按原有质量策略排序。4K 优先于 720p 的行为有合成样例回归，本轮在线样例实际可用源均为 1280×720，不把它们标成 4K。

只有目标笔记明确为 normal 图文时返回 NO_MEDIA；视频笔记缺少视频信息或媒体流返回 MEDIA_UNCONFIRMED，未知状态结构返回 EXTRACTOR_CHANGED，上层可继续现有通用解析流程。登录和验证码仍要求用户完成，不规避平台验证。

小红书页面获取合并为逐跳跟随同一次响应，最多 6 次请求。Cookie 只发给 HTTPS 小红书第一方域，短链域不携带笔记账号头；拦截非平台跳转、登录与验证终点、原链接已知笔记 ID 被更换的跳转。保留分享访问参数。

## 验证

| 检查 | 结果 |
| --- | --- |
| Android JVM 测试 | 86 项通过，包含 7 项新旧状态、ID、图文/视频、undefined、备用流和推荐内容隔离回归 |
| Android 15 模拟器实际应用解析 | 原先保存的主、备用视频 2/2 成功，返回笔记 ID 正确，各 6 个实际地址 |
| 实际视频下载及媒体库导出 | 备用视频 18,914,373 字节，1280×720、132,201ms、有音轨；生产 DownloadEngine.executeDownload、MediaVerifier 和 StorageExporter 链路通过 |
| 图文负向校验 | 两个图文样例在视频入口均明确返回 NO_MEDIA，并提示图文下载页；本轮未验收图文下载页的保存流程 |
| 运行环境 | API35 x86_64 模拟器，匿名会话、直连；测试成品已清理 |

在线解析测试使用工作目录里用户先前提供的私有样例，不将完整分享令牌或页面快照打入产品安装包。下载测试选用约 18.9 MB 的备用样例，未完整下载数百 MB 的主样例。

当前没有连接物理手机。本次报错的具体新链接尚未提供，因此不能声称已验证该条链接；真实账号、平台风控和特定内容权限仍需对应环境验收。Windows 与 iOS 本轮未修改，其他工作目录改动保留。

## 使用

覆盖安装 `release/1.7.3/OmniDownloader-1.7.3-arm64-v8a.apk`，重新粘贴原始分享链接解析。沿用 1.7.2 的 Cookie 文件修复和 1.7.1 的内置浏览器登录改进，无需清空应用数据。

测试结果见 TEST_RESULTS_1.7.3.json，APK 校验值见 release/1.7.3/SHA256SUMS.txt。最低 API26、目标 API34、ARM64 ABI 保持不变。

对照：[yt-dlp 官方小红书提取器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/xiaohongshu.py)目前同样读取旧桌面 noteDetailMap 路径；新移动结构的兼容依据是本轮实际获取的分享页，不是仅修改错误提示。

# Android 1.7.43：账号重新验证与请求警告

versionCode 102。仅交付 Android ARM64 安装包；未公开发布 GitHub，未替换本机 Web 或其他平台安装包。

## 账号重新验证

原流程可能把旧 Cookie 恢复到登录页，并立即通过自动捕获重新保存，在用户完成验证前关闭页面。现在账号设置中再次登录使用明确保存；标记为「需重新验证」的会话不再自动回填到浏览器，也不自动捕获、关闭验证页面。用户完成登录后点击保存，应用导入当前 Cookie 并更新会话状态。

未自动清理共享浏览器的 Cookie；用户仍可在页面中手动退出或更换账号。独立 Google 登录档案和凭据归属清理继续保留。

## 请求警告

X 和 Pixiv 不再人为设置 15/30/60 分钟固定冷却。遇到限流、登录失效或验证要求时，停止当前请求并保存警告，在应用前台弹窗显示。用户可选择「我已了解」，或进入账号管理；确认后可手动重试，不自动重启任务或轮换账号、代理。

保留原有请求间隔、跨进程共享记录和服务端明确指定的 Retry-After / x-rate-limit-reset 等待时间。弹窗会显示服务器指定的可重试时间，确认警告不会取消该等待。旧版本的人工冷却记录转换成警告；旧记录中能够识别出超过原人工冷却时长的服务端等待继续保留。损坏记录也转为需要确认的警告，不新增固定 15 分钟等待。

原生和 Python 共用同一警告 ID 与确认状态；后台或进程退出时产生的警告在下次前台启动显示。确认旧弹窗不能清除随后产生的新警告。X 原生下载保护、禁止在限制后切换公开接口、外部网络下载器回退保护继续有效。

## 验证

- 先加入回归测试，确认旧实现会为无服务端期限的身份拒绝添加 15 分钟等待；修复后 282 项 JVM 测试通过。
- 139 项 Python 测试通过，覆盖警告确认、服务端期限保留、旧记录迁移、过期确认及既有平台解析行为。
- 25 项 Android 15 x86_64 模拟器回归通过，涵盖原生/Python 警告传递、账号重新验证不捕获旧 SID、明确保存新 SID、无效会话不回填、Google 独立档案、Cookie 开关、实际解析 CLI 与跨进程保护。最终确认分发调整另复测 5 项相关用例。
- 正式包执行 R8 构建、Lint、签名校验与 UI 冒烟，覆盖真实应用内弹窗、确认持久化、跳转账号管理及 Google 档案创建/退出。QA 日志随安装包保存。

使用合成 Cookie、本地网页和无网络的受控拒绝场景；没有操作真实 Google/X/Pixiv 账号。未验证实体 ARM64 手机，ARM64 正式包在模拟器中仅验证界面与资源解压，原生引擎验证使用 x86_64 测试包。请求警告不能保证平台账号不会受限。
